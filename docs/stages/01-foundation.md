# Этап 1 — основа интерфейса

Дата: 15 ноября 2026, Europe/Paris.
Статус исполнителя: реализовано и проверено локально; приёмка за координатором.
Коммиты, push и публикация исполнителем не выполнялись. `docs/DELIVERY.md`
не редактировался исполнителем (изменения координатора в общей папке сохранены).

## Реализовано

- React 19.3.1, TypeScript 6.0.3, Vite 8.3.8; lockfile, строгая типизация,
  ESLint, Vitest 5.1.0, Testing Library и Playwright 1.65.1.
- Пять экранов: главная, проба тренировки, результаты, карта, настройки.
  Hash-навигация работает с Back и прямыми ссылками на статическом хостинге.
- RU/ES в отдельных JSON, типизированные ключи и параметры, ES по умолчанию;
  обновляется `html.lang`. Переключатель доступен на каждом экране.
- Базовый SVG-лис без внешних изображений/шрифтов, спокойная космическая тема,
  адаптивные карточки, нижняя навигация телефона, боковой блок на широком экране.
- `viewport-fit=cover`, `env(safe-area-inset-*)`, интерактивные кнопки от 52 px,
  видимый focus, skip link, подписи полей, live feedback, reduced motion.
- Ввод собственной клавиатурой, физической клавиатурой и через нативное поле
  с `inputMode=numeric`. Допускается до 3 ASCII-цифр, удаление, Enter,
  блокировка пустого подтверждения, повтор пробы и сохранение значения при
  смене способа ввода.
- Переключение системного режима использует `flushSync` перед `focus` внутри
  пользовательского жеста, чтобы Safari увидел новое значение inputMode.
  Enter на кнопке keypad подтверждает ответ один раз; Enter на переключателе
  режима сохраняет обычную семантику кнопки. Нативный input обрабатывает свои
  клавиши сам, без дублирующего обработчика.
- Анимации включены по умолчанию и отключаются настройкой или reduced motion;
  звук выключен. Настройки пока в памяти и это явно сообщено в интерфейсе.
- Pure-domain контракты `Exercise`, `ExerciseEngine`, `Clock`, `RandomSource`
  без зависимости от React. Реализаций движка на этом этапе нет.
- `base: '/MathHero/'`; в `dist` только HTML, CSS, JS и favicon.

## Честные границы предварительной версии

Тренировка — явно подписанная проба ввода с примером 7 × 8. Она только
подтверждает введённое число, не оценивает ответ, не измеряет скорость,
не начисляет звёзды и не создаёт историю. На главной 0 звёзд и нет оценки
освоения. Результаты пусты; карта показывает 144 непроверенные клетки без
фиктивных уровней и истории. Раздел трудных примеров пока информационный.

Разрешённая неоднозначность: ТЗ говорит о пяти разделах, но в перечислении
называет четыре; пятым выбран экран настроек из последующих разделов ТЗ.
Навигация использует hash для совместимости с Pages. Хранение языка и
предпочтений будет подключено к IndexedDB вместе с данными, отдельного
временного localStorage-хранилища нет.

### Зависимости и ограничения среды, обнаруженные в процессе

- TypeScript latest был 7.0.2, но typescript-eslint 8.72.2 поддерживает
  TypeScript `<6.1.0`; поэтому закреплён 6.0.3. Все peer dependencies
  установлены без `--force`/`--legacy-peer-deps`.
- Первоначальный audit: 7 moderate записей в цепочке lint-инструментов,
  все из-за одной уязвимости minimatch. Точечный scoped override
  `@typescript-eslint/typescript-estree → minimatch 11.0.1` устранил
  [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
  Проверены engines/exports и используемый API; lint после override прошёл.
  `npm ci` с окончательным lockfile сообщает **0 vulnerabilities**.
- Установка зависимостей/браузеров выполнена с обычным `require_escalated`.
  Первый запуск Playwright в песочнице не дошёл до тестов (ожидание preview)
  и был остановлен. Escalated-запуски прошли. Это не засчитано как пройденный
  sandbox-прогон.
- Первая попытка `npm ci` при ещё запущенном preview завершилась EPERM на
  занятом native binding Rolldown. После остановки собственного процесса
  повторная чистая установка прошла. Политики/права системы не менялись.
- Источники совместимости: [Vite](https://vite.dev/guide/),
  [Vitest](https://vitest.dev/guide/),
  [Playwright](https://playwright.dev/docs/browsers), метаданные официального npm.

## Что ещё не проверено и не реализовано

- **Физические iPhone/iPad не проверены.** WebKit на Windows не равен Safari
  на устройстве. Открытие настоящей системной цифровой клавиатуры, поведение
  её visual viewport и реальные ненулевые safe-area insets требуют проверки
  пользователем после готовности MVP. В автоматизации проверены DOM/inputMode,
  фокус и ввод. CSS safe-area включён, device-safe-area acceptance не заявляется.
- В коротком landscape допускается вертикальная прокрутка; горизонтальной
  нет в проверенных профилях. Не заявляется размещение всей тренировки на
  одном экране телефона во всех размерах и с открытой системной клавиатурой.
- Нет движка, полной диагностики, адаптации, сессий, IndexedDB, backup,
  реальной статистики, наград, интерактивной истории ячеек, PWA или публикации.
- Нет измерения целевого старта ≤3 s на физическом устройстве/сети.
- GitHub Actions здесь не создавались и их версии не выбирались; проверить
  совместимость конкретных Actions и публикацию только dist на этапе 5.
